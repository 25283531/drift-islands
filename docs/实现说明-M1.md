## 2. 关键实现决策

### 2.1 存储与运行形态

- 生产 / 测试环境：PostgreSQL + Redis（`DB_TYPE=postgres`），由 `docker compose` 编排；数据库结构由 `migrations/001-init.sql` 建立，应用不做自动改表（`synchronize: false`）。
- 本地开发 / CI：`better-sqlite3` + 进程内 KV（`DB_PATH=:memory:` 或文件）。同一套 TypeORM 实体、同一套业务代码，避免两套逻辑。列类型在 `src/database/column-types.ts` 按驱动切换（`jsonb`/`simple-json`、`timestamptz`/`datetime`）。
- 未配置 `REDIS_URL` 时 `KvService` 退化为进程内实现，单实例可用；多实例必须配 Redis（在线状态、遭遇兜底计数、禁言 TTL、配额缓存会不共享）。

### 2.2 世界时钟与时间折算

- 每 20 现实秒推进 1 世界分钟（`WORLD_TICK_MS` 控制扫描频率，按 `last_tick_at` 差值补算）。
- 1 世界日 = 1440 世界分钟；世界分钟 0–959 为白天、960–1439 为夜晚（2:1）。
- 航行时间立即推进世界时钟：`距离 ÷ 船速` 世界小时；单次上限 2 世界小时（20 海里），漂流 1 世界小时。
- 洋流按世界日确定性生成（同一天方向固定），与洋流夹角 ≤ 30° 视为顺流，不耗燃料。
- 燃料不足时按剩余燃料缩短航程并提示（设计说明的“短缺惩罚”数值待定，掉落 / 掉血不在 M1）。

### 2.3 遭遇与「2 世界小时必遇」兜底

- 遭遇视野：白天 12 海里、夜晚 6 海里（M1 先行值，`ENCOUNTER_RANGE`）。
- 连续航行累计 120 世界分钟未遭遇时，洋流把船送到最近岛屿的遭遇圈内（并落在影响半径内，保证“遇得到也进得去”），同时给出 `warning.current_guidance`。
- 预置岛屿：`锈锚岛`（12, 8），影响半径 8 海里，3 只怪物（0/1/2 级），出生点距岛约 14.4 海里，符合“2 世界小时内必遇”。

### 2.4 AI 叙述与成本

- `NarratorService` 始终先产出模板文本；配置了 `AI_BASE_URL` + `AI_API_KEY` 时才调用 OpenAI 兼容接口润色，且**不得改写数字**（prompt 明确约束）。
- 输出再过一次红线检查；命中或调用失败一律回退模板，玩法不中断。
- 每玩家每日 AI 调用预算默认 200 次，按 Asia/Shanghai 自然日计；超预算 `degraded=true`，直接走模板。
- 未配置模型时全程模板（本仓库默认状态）。LLM 路径已实现并有降级保护，但**没有可用密钥，本次未对真实模型做线上验证**（见 §7）。

### 2.5 内容红线与 AI 行为边界

- 红线六类用规则词表实现（`ContentFilterService`），只在“超出末世生存合理范围”的表述上命中；`击杀 / 流血 / 战斗` 属于题材内叙述，不拦。
- 玩家命中红线：消息 `visibility=quarantined`（只回给发言者）+ `warning` + `moderation_records` 留档；梯度：第 1 次提示并隔离，第 2 次禁言 1 世界日（8 现实小时，Redis TTL），第 3 次起封禁并等人工复核。
- AI 只回应游戏相关问题；闲聊不回应。医疗建议、自杀、毒品 / 枪支弹药 / 危险品制作方法只做简短拒绝（自杀附一句建议寻求现实专业帮助）；现实制作方法类内容**不隔离**（设计 v1.4）。

### 2.6 战斗

- 回合 15 秒（`COMBAT_ROUND_MS`），玩家提交后若所有存活玩家都已行动则立即结算，否则超时按防守。
- 行动顺序按速度降序，同速随机；怪物默认攻击玩家，4 级以上“可指挥集火”是 M3 内容，M1 只有单玩家，未实现指挥。
- 怪物血量 ≤30% 时按等级判定逃跑（1–3 级 50%、4–6 级 20%、7 级不逃）。
- 玩家逃跑：50% + 5% × 速度差，封顶 90%、最低 10%。
- 战斗会话落 `combat_sessions`（参与者快照、行动、每回合日志），用于复盘。
- 战斗结束：胜利记录 `experience_logs`；失败按死亡处理（状态 `dead`，3 秒后在海域随机坐标复活，血量 30%）。**物品掉落与晶核掉落属于 M2，M1 未实现。**

### 2.7 与 M0 的接口差异（新增，均已在前端与文档使用）

M0 未定义聊天消息的服务端广播事件，M1 补充如下事件（均向后兼容）：

| 事件 | 方向 | 用途 |
| --- | --- | --- |
| `chat_message` | 服务端 → 客户端 | 玩家 / AI / 系统消息广播（含 `visibility`） |
| `chat_history` | 服务端 → 客户端 | 登录 / 进岛 / 离岛时补历史消息 |
| `authenticated` | 服务端 → 客户端 | 登录成功回执（角色、船、频道） |
| `channel_changed` | 服务端 → 客户端 | 海频道 ↔ 岛屿子频道切换 |
| `combat_finished` | 服务端 → 客户端 | 战斗结束与结果叙述 |

## 3. 数据库（22 张表）

`migrations/001-init.sql` 与 `src/database/entities/` 一一对应：users、characters、ships、islands、island_points、monster_kinds、monsters、items、crystals、skills、teams、channels、chat_messages、world_state、world_events、combat_sessions、experience_logs、moderation_records、model_pool、resource_registry、dead_drops、ai_quotas。

索引按 M0 §1.23；`chat_messages` 增加 `kind` 字段区分玩家 / AI / 系统（M0 未列，用于前端渲染与审核追溯）。

Redis 键：

| 键 | 用途 | TTL |
| --- | --- | --- |
| `encounter:char:<id>` | 连续未遭遇世界分钟（兜底） | 6 小时 |
| `mute:<userId>` | 禁言到时 | 1 世界日 |
| `quota:<userId>:<date>` | 当日 AI 调用计数 | 24 小时 |
| `cache:narration:<key>` | 叙述缓存 | 10 分钟 |

## 4. 运行方式

### 本地（SQLite，零外部依赖）

```bash
npm ci
cp .env.example .env
npm run build
npm run start        # http://localhost:3000
npm test             # 单元 + 端到端
```

### 服务器（PostgreSQL + Redis，容器内存受限）

```bash
cd /opt/drift-islands
cp .env.example .env   # 填 DB_PASSWORD / JWT_SECRET
docker compose up -d --build
curl http://127.0.0.1:3000/health
```

内存上限：app 384 MB、PostgreSQL 320 MB、Redis 64 MB（服务器 2 GB，另有 WordPress 站点）。

## 7. 已知限制（M1 明确不做 / 待补）

1. **未接真实模型**：仓库默认无密钥，叙述走模板；LLM 调用路径仅有代码与降级保护，未做真实模型效果与成本验证。
2. 登录是“显示名换会话”，无密码 / 无第三方账号，仅限原型；公测前必须替换（M6 安全复核项）。
3. 物品、晶核、技能、造岛、驻扎、交易、PvP、团队、疲劳与猝死、保护期逻辑属 M2/M3；`characters` 等表已预留字段，但对应事件返回未实现或仅保留字段。
4. 内容红线是规则词表，存在绕过空间；M3 审核层补模型复核与人工复核流程。
5. 单实例假设：战斗回合计时器在进程内，多实例部署前需要迁移到 Redis / 独立 tick 服务。
6. 断线宽限期 30 秒已实现状态流转；重新登录会恢复到角色所在岛屿与战斗回合。
