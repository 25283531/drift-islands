## 2. 指标口径（5.2）

`GET /api/v1/admin/metrics` 返回：

| 字段 | 口径 |
| --- | --- |
| `players.online` | characters.status = online |
| `players.active_24h` | `last_seen_at` 在 24 小时内 |
| `players.new_today` | 当天创建的角色 |
| `islands.total` | 岛屿总数 |
| `combat.completion_rate` | finished / 全部战斗会话 |
| `ai.calls_today` | 当天 `ai_quotas.calls_used` 求和 |
| `ai.degraded_users_today` | 当天触发降级的用户数 |
| `content.violations_total` / `by_action` | 审核记录分布（提示/禁言/封禁） |
| `content.pending_reports` | 待处理举报 |
| `travel.encounter_rate` | 遭遇次数 / 航行次数（Redis 计数，自部署起累计） |
| `feedback.new` | 待处理反馈 |

已知限制：
- 航行/遭遇计数是进程内 Redis 累计值，重启会归零；后续可改为按世界日写表。
- 暂无「次日留存」直接口径，需按 `characters.created_at` + `last_seen_at` 做二次统计（内测报告阶段补 SQL）。
- 在线时长依赖 `last_seen_at`，目前只在鉴权/心跳时刷新。

## 3. 问题收集流程（5.3）

1. 玩家在聊天室发 `反馈 问题描述`，或调用 `POST /api/v1/feedback`。
2. 后台 `GET /api/v1/admin/feedback?status=new` 查看。
3. 处理完调用 `POST /api/v1/admin/feedback/:id/close`，记录处理人。
4. 严重 Bug 归入问题清单，修复后回归；每条都要有复现步骤与版本号。
