# 漂流岛屿 · M3.5 文字交互改造

## 1. 为什么改

试玩反馈：侧栏按钮点“攻击”没反应，游戏只能靠面板操作、无法用文字控制。
原因有两个：

1. 战斗回合开始时前端执行了 `setCombatButtons(false)`，把“攻击/防御/逃跑”全部禁用，
   正好卡在唯一能提交行动的时机；回合结算后又只在前端恢复，玩家看起来就是“点不动”。
2. 交互全部挂在侧栏按钮上，聊天框只能说话，不能下指令。

本次改造把主交互搬到聊天室，侧栏降级为信息展示。

## 2. 交互原则

- 一切操作都可以在聊天框里用自然语言/关键词完成，不需要点按钮。
- 系统用“叙述”消息回复，和聊天记录在同一条时间线上。
- 侧栏 `<details>` 默认折叠，只用于看数值与面板；紧急时仍可点按钮兜底。
- 问句优先当聊天：以 `?` / `？` 结尾的消息交给 AI 回答，不当作指令。

## 3. 指令表

| 输入 | 行为 |
|---|---|
| 菜单 / 帮助 | 列出全部操作 |
| 启航 | 追问方向 → 追问航程 → 航行 |
| 0–359 或 东北/西南 | 作为方向回答 |
| 数字（1–30） | 作为航程回答 |
| 漂流 | 随洋流漂一段，不耗油 |
| 附近 | 报最近岛屿的方向、距离、是否够近 |
| 上岛 / 离岛 | 靠岸 / 回船 |
| 攻击 / 防御 / 逃跑 | 战斗中提交对应行动；不在战斗时提示 |
| 搜刮 | 在岛上收集，回复成功率与掷点 |
| 造岛 | 进入“一段话描述”流程 |
| 确认 / 取消 | 确认造岛 / 放弃当前流程 |
| 技能 | 已领悟技能与资质 |
| 组队 / 建队 队名 / 队伍 | 建队 / 查看队伍 |
| 状态 | 生命、疲劳、保护期、船况、位置 |
| 交易 | 给出面对面交易的下一步提示 |

## 4. 状态机

```
空闲 ──启航──▶ 等方向 ──数字/方位──▶ 等航程 ──数字──▶ 航行 ──▶ 空闲
空闲 ──造岛──▶ 等一段话 ──段落──▶ 逐个补缺 ──回答──▶ 待确认 ──确认──▶ 创建
任意 ──取消──▶ 空闲
```

状态只存在当前角色的网关内存里，30 分钟无操作自动失效。

## 5. 一段话造岛

1. 玩家发“造岛”，系统要求用一段话描述（名字、样子、规矩、产出、怪物、数量、等级）。
2. 规则层先抽取：岛名、描述、规则（“规则：”后按；拆分）、资源关键词、怪物名/数量/等级、
   建筑/防御/武器。
3. 抽不到的字段交给小模型补全（JSON），模型失败不影响流程。
4. 仍缺的字段按顺序逐条追问，已识别的内容先复述一遍，避免重复问。
5. 信息齐了提示“回复确认”，确认后走原有校验（红线、威胁预算、间距、配额）并落库。

## 6. 前端变化

- 回合开始恢复按钮可用；攻击目标改为“活着的怪物”，不再依赖 DOM 列表。
- 新增 `command_action` 桥：服务端决定“上岛/离岛”时，前端代为触发原有事件。
- 侧栏 M2/M3 面板收进“信息与面板（点开看数值，操作直接打字）”，默认折叠。
- 聊天提示改为：菜单、启航、漂流、附近、上岛、攻击、搜刮、造岛。

## 7. 测试

- 单元：`test/unit/commands.spec.ts` 6 项（意图、方向、航程、菜单、造岛抽取与缺口）。
- 端到端：`test/e2e/chat-command.spec.ts` 3 项（菜单、启航→方向→航程、造岛追问与取消）。
- 回归：M1 聊天/红线测试保持通过；全量 13 个文件 72 项。

## 8. 已知限制

1. 文字指令是关键词匹配，复杂句式（“往东北走五海里”）尚未合并解析。
2. 战斗中的“攻击谁”默认选第一个活着的怪物，多目标选择待补。
3. 交易接受依赖对方在线并主动回“接受交易”，没有交易行/邮件式挂单。

## 9. 补充（对话式交易/入队/驻扎、指定目标、漂流保底）

- **交易**：发「交易」→ 问对方角色名 → 问给出什么（可回「无」）→ 问要什么 → 汇总 → 「确认交易」发出；
  对方收到叙述后回「接受交易」或「拒绝交易」。物品按名字匹配，支持简称。
- **入队**：发「入队 队名」直接加入（队满 5 人拒绝）；只发「入队」会追问队名。
- **驻扎**：发「驻扎」→ 提示「确认驻扎」→ 建立基地。
- **指定目标**：战斗中发「打第2只」「攻击3」「第二只」或「打溺尸」，会选中对应怪物并回报“第 n 只”。
- **漂流保底**：修复了船贴海域边界时航程被截断为 0、世界时间不推进、遭遇计数不增长的死循环；
  贴边时漂流方向自动掰回海域中心，且漂流固定消耗 1 世界小时；漂流的遭遇保底阈值降为 90 分钟，
  连续两次漂流内必定被洋流送到最近岛屿。
- **叙述提速**：线上免费模型额度打满时，单段叙述会重试 3×8 秒，导致遭遇事件被拖到 20 秒后才可见。
  航行与遭遇叙述改为「4 秒内模型没回来就用模板」，事件不再被 AI 队列阻塞；日志中可看到 `遭遇判定` 行便于排查。

## 10. 硅基流动接入（补充模型额度）

- 新增第三个 provider `siliconflow`（OpenAI 兼容，`https://api.siliconflow.cn/v1`），环境变量：
  `SILICONFLOW_API_KEYS`、`SILICONFLOW_MODELS`、`SILICONFLOW_BASE_URL`；`docker-compose.yml` 已透传。
- 线上模型配置：小模型 `Qwen/Qwen2.5-7B-Instruct`、`Qwen/Qwen2.5-14B-Instruct`，大模型 `Qwen/Qwen2.5-72B-Instruct`。
  Qwen3 系列是推理模型，8 秒内经常出不来，不放进池子。
- 候选排序改为「provider 优先级 → 失败次数 → 调用次数」，硅基流动优先；否则前三次尝试会被已限流的
  OpenRouter 占满，新 provider 永远轮不到。
- 实测：游戏内提问 3 秒内回话，航行叙述不再降级（`degraded:false`）。

## 11. 战斗体验（不再每回合手打「攻击」）

- **默认自动开火**：回合内没提交动作，不再自动防守，而是自动攻击当前锁定目标；发过一次「打第2只」后会一直打第 2 只，直到它倒下。
- **每回合硬指标**：`combat_round_start` / `combat_round_result` 新增 `you`（HP/攻击/防御）、`queue`（怪物序号、HP、是否存活）、`status_text`，并直接附在叙述末尾，例如：
  `你 85/100｜攻 6 防 2｜1.溺尸 11/16 2.拾荒者 30/30 3.藤壶蟹 55/55`
- **面板常显**：战斗面板显示自己的 HP/攻击/防御与怪物队列血条，点怪物即可锁定目标，按钮仍保留；提示“不操作会自动攻击”。
- 回归：`moderation.spec` 改为验证超时自动开火、怪物掉血与状态行存在；线上实测两回合无操作，溺尸 16→11。

## 12. 同时参战怪物上限（按等级）

- **规则**：同时参战怪物数 = `1 + 人物等级`，上限 4。

  | 人物等级 | 同时参战上限 |
  |---|---|
  | Lv0 | 1 只 |
  | Lv1 | 2 只 |
  | Lv2 | 3 只 |
  | Lv3 及以上 | 4 只 |

- **为什么**：Lv0 一次面对锈锚岛 3 只怪每回合掉约 15 血，两回合就濒死；上限压到 1 只后同样打法每回合约 2 血，新手有时间学会攻击、锁定与逃跑。
- **怎么选怪**：进岛时按怪物等级从低到高取前 N 只；没被惊动的留在岛上，再进一次岛就打下一批。
- **提示**：超出上限时额外发一条 `warning`：
  `以你现在的身手，一次只能应付 1 只；其余 2 只还在暗处观望。`（`type: monster_limit`）
- **实现**：
  - `src/game/m2.ts`：`CONCURRENT_MONSTERS` 与纯函数 `concurrentMonsterLimit(level)`；
  - `src/islands/islands.service.ts`：`enter()` 在保护期过滤之后按键等级截取参战怪物，并生成 `monster_limit` 提示；
  - `src/combat/combat.service.ts`：`startCombat()` 只接受进岛结果里的这批怪（同时从库里重读血量、跳过被其他会话占用的怪），数量限制不会被绕过。
- **与遗留回收的配合**：卡在 `combat` 的怪会先被 `recover()` 释放回 `idle`（0 血则回满），再按上限挑选，避免上一场残留把本场怪物“占满”。
- **测试**：`test/unit/m2-rules.spec.ts` 覆盖 0/1/2/3/7 级上限；`test/e2e/combat-monster-limit.spec.ts` 验证 Lv0 进岛只有 1 只怪且收到提示。
