# 漂流岛屿 · M3.5 文字交互改造

## 1. 为什么改

试玩反馈：侧栏按钮点“攻击”没反应，游戏只能靠面板操作、无法用文字控制。
原因有两个：

1. 战斗回合开始时前端执行了 `setCombatButtons(false)`，把“攻击/防御/逃跑”全部禁用，
   正好卡在唯一能提交行动的时机；回合结算后又只在前端恢复，玩家看起来就是“点不动”。
2. 交互全部挂在侧栏按钮上，聊天框只能说话，不能下指令。

本次改造把主交互搬到聊天室，侧栏降级为信息展示。

## 2. 交互原则

- 一切操作都可以在聊天框里用自然语言/关键词完成，不需要点按钮。
- 系统用“叙述”消息回复，和聊天记录在同一条时间线上。
- 侧栏 `<details>` 默认折叠，只用于看数值与面板；紧急时仍可点按钮兜底。
- 问句优先当聊天：以 `?` / `？` 结尾的消息交给 AI 回答，不当作指令。

## 3. 指令表

| 输入 | 行为 |
|---|---|
| 菜单 / 帮助 | 列出全部操作 |
| 启航 | 追问方向 → 追问航程 → 航行 |
| 0–359 或 东北/西南 | 作为方向回答 |
| 数字（1–30） | 作为航程回答 |
| 漂流 | 随洋流漂一段，不耗油 |
| 附近 | 报最近岛屿的方向、距离、是否够近 |
| 上岛 / 离岛 | 靠岸 / 回船 |
| 攻击 / 防御 / 逃跑 | 战斗中提交对应行动；不在战斗时提示 |
| 搜刮 | 在岛上收集，回复成功率与掷点 |
| 造岛 | 进入“一段话描述”流程 |
| 确认 / 取消 | 确认造岛 / 放弃当前流程 |
| 技能 | 已领悟技能与资质 |
| 组队 / 建队 队名 / 队伍 | 建队 / 查看队伍 |
| 状态 | 生命、疲劳、保护期、船况、位置 |
| 交易 | 给出面对面交易的下一步提示 |

## 4. 状态机

```
空闲 ──启航──▶ 等方向 ──数字/方位──▶ 等航程 ──数字──▶ 航行 ──▶ 空闲
空闲 ──造岛──▶ 等一段话 ──段落──▶ 逐个补缺 ──回答──▶ 待确认 ──确认──▶ 创建
任意 ──取消──▶ 空闲
```

状态只存在当前角色的网关内存里，30 分钟无操作自动失效。

## 5. 一段话造岛

1. 玩家发“造岛”，系统要求用一段话描述（名字、样子、规矩、产出、怪物、数量、等级）。
2. 规则层先抽取：岛名、描述、规则（“规则：”后按；拆分）、资源关键词、怪物名/数量/等级、
   建筑/防御/武器。
3. 抽不到的字段交给小模型补全（JSON），模型失败不影响流程。
4. 仍缺的字段按顺序逐条追问，已识别的内容先复述一遍，避免重复问。
5. 信息齐了提示“回复确认”，确认后走原有校验（红线、威胁预算、间距、配额）并落库。

## 6. 前端变化

- 回合开始恢复按钮可用；攻击目标改为“活着的怪物”，不再依赖 DOM 列表。
- 新增 `command_action` 桥：服务端决定“上岛/离岛”时，前端代为触发原有事件。
- 侧栏 M2/M3 面板收进“信息与面板（点开看数值，操作直接打字）”，默认折叠。
- 聊天提示改为：菜单、启航、漂流、附近、上岛、攻击、搜刮、造岛。

## 7. 测试

- 单元：`test/unit/commands.spec.ts` 6 项（意图、方向、航程、菜单、造岛抽取与缺口）。
- 端到端：`test/e2e/chat-command.spec.ts` 3 项（菜单、启航→方向→航程、造岛追问与取消）。
- 回归：M1 聊天/红线测试保持通过；全量 13 个文件 72 项。

## 8. 已知限制

1. 交易、组队加入、驻扎等仍以提示或侧栏兜底，尚未全部做成多轮对话。
2. 文字指令是关键词匹配，复杂句式（“往东北走五海里”）尚未合并解析。
3. 战斗中的“攻击谁”默认选第一个活着的怪物，多目标选择待补。
