## 2. 造岛

### 2.1 模板问题（12 问，按顺序）

岛名 → 描述 → 规则（3–5 条）→ 资源方向 → 怪物（预置库名称或自由描述）→ 最高等级 → 数量 → 是否集中 → 集中点（选填）→ 建筑（选填）→ 防御（选填）→ 武器（选填）。

- 不可跳过的题：名字、描述、规则、资源、怪物、最高等级、数量。
- 选填题留空或输入「跳过」即跳过；`island_create_summary` 返回草稿与校验问题，`island_create_confirm` 才真正落库。
- 模板问答只收集定义，不暴露坐标。

### 2.2 校验（规则 + 数字，AI 不参与裁决）

- 岛名 2–16 字；描述 ≥ 6 字；规则 3–5 条、单条 ≤ 120 字。
- 每条规则先过内容红线（`ContentFilterService.checkInput`），再匹配「无敌 / 无法被攻击 / 无限资源 / 秒杀 / 免疫」等改写全局规则的表述，命中即拒绝。
- 怪物等级 0–7，且 ≤ `min(7, 2 + floor(世界日 / 5))`；单种数量 1–12。
- 威胁度 = Σ（等级 × 数量）+ 防御项 × 2 + 武器项 × 2，需 ≤ `50 + 10 × 世界日`。
- 创建配额 = `1 + floor(等级 / 5)`，按 `creator_user_id` 计数。

### 2.3 随机放置

在 `sea_radius_nm` 内均匀取点，要求：
- 与出生点距离 ≥ 10 海里（出生区禁建）；
- 与所有已有岛屿中心距离 ≥ 15 海里；
- 最多尝试 400 次，失败返回「当前海域没有满足间距的位置」。

影响半径 3–8 海里，按怪物数量与最高等级计算。坐标只写进数据库，**创建接口、`island_created` 事件、岛主面板都不返回 x/y**（防自肥）。

## 3. 收集与裁决

`collect { intent }`（也可带 `island_id`，默认当前所在岛）：

1. **意图提取**：`ResourceRegistryService.classify` 先按别名 / 关键词归一（汽油、柴油 → 燃料；罐头、干粮 → 食物），规则不中再调小模型，模型也失败则归「杂项」并登记。
2. **数字判定**：成功率 = 55% + (人物等级 − 岛最高怪等级) × 5% + 科研等级 × 4% − 岛上有活怪 10%，钳制 15%–90%；一次随机数决定成败，成功产量 1–(3 + 科研等级)，高威胁岛减 1。
3. **结果落库**：成功则从岛屿库存扣减、写入角色背包、`islands.resources_taken += 数量`；失败只扣体力。
4. **叙述**：模板固定，`arbitration_result` 同时返回 `chance / roll / amount`。AI 只做措辞，不能改写判定——这三个数字由服务端单独返回，客户端可直接核对。

## 4. 船只四条线

| 线路 | 每级消耗（目标等级 n） | 效果 |
| --- | --- | --- |
| 防御 | 零件 2n + 燃料 n | 耐久上限 +15n，并补满新增耐久 |
| 武器 | 零件 2n + 科技 n | 火力 +4n |
| 生活 | 食物 2n + 水 2n | 货仓 +6n，体力上限 +5n |
| 科研 | 科技 2n + 零件 n | 收集成功率/产量加成（M2 先按 `research_lv` 计） |

每条线上限 5 级；材料按堆栈顺序扣减，不足时返回「升级需要 零件×4（现有 1）」这类明细。

## 5. 晶核

- 怪物死亡按等级掉落晶核：能量 = `100^(N-1)`，0 级 = 0.01。
- 升级需求：0→1 为 0.1，L→L+1 为 `10 × 100^(L-1)`（即 10 颗同级晶体）。
- 越级吸收：一次最多吸收「当前等级升一级所需能量」，剩余能量保留在晶体行里，可以后再吸。
- 升级时生命上限 +10/级、体力上限 +5/级并回满（M2 先行数值）。
- 战斗胜利自动把晶核收进击杀者背包（M2 简化：不做地面拾取）；`combat_finished` 会带上 `crystals` 列表。

## 6. 驻扎与岛主面板

- `settle`：必须人在岛上；无主或自己已有则成为岛主，初始化基地三级设施各 1 级。
- `base_build`：防御 / 储物 / 设施，各上限 3 级，消耗零件、科技、食物。
- `base_store` / `base_take`：岛主在背包与岛屿库存间搬运资源（岛屿库存带 `storage` 标签）。
- 面板字段：访问次数、被拿走资源量、防御力（防御项 × 2 + 基地防御等级 × 5）、火力（活怪攻击和）、怪物数量与最高等级、基地等级、仓库清单；**不含坐标**。

## 7. 多模型接入（英伟达 NIM + OpenRouter）

`AiGatewayService` 支持多家 OpenAI 兼容服务，同层多模型、失败自动切换：

- 环境变量：
  - `NVIDIA_API_KEYS`（逗号分隔多密钥）、`NVIDIA_BASE_URL`、`NVIDIA_MODELS`（`small:模型,large:模型`，不写前缀默认 small）。
  - `OPENROUTER_API_KEYS`、`OPENROUTER_BASE_URL`、`OPENROUTER_MODELS`。
  - 兼容旧的 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL_SMALL` / `AI_MODEL_LARGE`。
- 选择策略：同层优先 → 跳过冷却中的模型 → 按调用次数均衡；单次调用最多试 4 个模型；失败模型冷却 60 秒。
- 密钥只放服务器 `.env`，不进仓库；`describe()` 可供诊断，不返回密钥。
- 输出仍走红线二次审核；模型不可用时自动回落模板叙述。
