# drift-islands M0：数据模型与接口定义

> 状态：M0 交付物。依据：设计说明 v1.4（定稿）。技术选型见设计说明 §6：TypeScript + NestJS 模块化单体，PostgreSQL + Redis，WebSocket 实时通信，LLM 路由（复用 L0–L3 路由思路）。
>
> 本文档只定义数据与接口，不写业务实现。M1 按本文档建表、接事件。

## 0. 约定

- **时间**：世界日 / 世界时。1 世界日 = 8 现实小时；1 世界时 = 20 现实分钟；1 世界日 = 24 世界时。白天为世界时 0–15（16 世界时），夜晚为世界时 16–23（8 世界时）。世界时间以 `(world_day, world_minutes)` 表示，`world_minutes ∈ [0, 1440)`，1 世界分钟 = 20 现实秒。
- **坐标**：单位为海里，浮点数 `(x, y)`；海域以 `(0, 0)` 为中心，半径 `sea_radius_nm`。位置播报保留 1 位小数。
- **ID**：一律 UUID（主键）；外键同类型。时间戳一律 `TIMESTAMPTZ`（现实时间）。
- **数字单位**：晶核能量单位（1 级晶体 = 1 单位）；船速单位为海里/世界小时；距离单位为海里。
- **枚举**：代码中用英文常量（如 `online` / `offline` / `grace` / `in_combat`），含义见各表说明。
- **JSONB**：半结构化数据（规则、配置、技能池、参与者快照）用 JSONB，不另建表。
- **追溯**：每个实体 / 接口后标注来源条款（如 `§3`、`§4.2`），M1 实现时可反查设计说明。

## 1. 实体模型（PostgreSQL）

### 1.1 users（用户 / 账号）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID PK | 用户 ID |
| display_name | TEXT | 显示名 |
| status | TEXT | `normal` / `muted`（禁言）/ `banned`（封禁），见 §4.4 |
| created_at | TIMESTAMPTZ | 注册时间 |

### 1.2 characters（角色 / 人物）§3、§4.2

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID PK | 角色 ID |
| user_id | UUID FK users | 所属用户 |
| name | TEXT UNIQUE | 角色名（团队称号另行展示，不拼进名字） |
| level | INT，默认 0 | 等级；新手 0 级开局 |
| crystal_energy | NUMERIC，默认 0 | 当前等级进度（单位）；升一级需 10 颗同级晶体 |
| aptitude | TEXT | 资质方向：`body`（肉体强化）/ `magic`（法术强化）/ `light`（光）/ `dark`（暗）/ `element`（元素）/ `martial`（武技）；创建时均匀随机 |
| hp / max_hp | INT | 血量 / 上限 |
| stamina / max_stamina | INT | 体力 / 上限 |
| speed | INT | 速度（战斗回合排序依据，见 §4.2） |
| x / y | DOUBLE | 当前坐标；乘船时与船同步 |
| ship_id | UUID FK ships，可空 | 所在船只；为空表示在岛上或徒步 |
| island_id | UUID FK islands，可空 | 所在岛屿；为空表示在海上 |
| team_id | UUID FK teams，可空 | 所属团队 |
| protection_level | INT | 入场时选择的保护期等级（≤ 人数最多的等级） |
| protection_active | BOOL | 保护是否生效（当前等级 < 保护期等级） |
| fatigue | NUMERIC 0–100 | 疲劳度；超时在线后累积 |
| fatigued_world_days | INT，默认 0 | 连续疲劳世界日（猝死判定用） |
| online_seconds_today | INT，默认 0 | 当日在线现实秒数；上限 8 现实小时 |
| status | TEXT | `online` / `offline` / `grace`（断线宽限期 30 秒内）/ `in_combat`（战斗中不可下线）/ `dead` |
| created_at / last_seen_at | TIMESTAMPTZ | 创建 / 最后在线 |

### 1.3 ships（船只）§4.2

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID PK | 船只 ID |
| captain_id | UUID FK characters | 船长；船长死亡后可交团队其他人驾驶 |
| name | TEXT | 船名 |
| durability / max_durability | INT | 耐久 / 上限（防御线升级提升） |
| speed | DOUBLE | 船速，海里/世界小时；初始 10 |
| cargo_capacity | INT | 货仓容量 |
| weapon_power | INT | 火力（武器线升级提升） |
| defense_lv / weapon_lv / living_lv / research_lv | INT，默认 0 | 四条升级线等级：防御 / 武器 / 生活 / 科研 |
| fuel | NUMERIC | 燃料 |
| x / y | DOUBLE | 船只坐标 |
| created_at | TIMESTAMPTZ | 创建时间 |

### 1.4 islands（岛屿）§3、§4.1、§4.2

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID PK | 岛屿 ID |
| creator_user_id | UUID FK users | 创建者（仅用于面板与归属，不可见坐标） |
| name | TEXT | 岛名 |
| x / y | DOUBLE | 坐标；系统随机分配，创建者不可见 |
| radius | DOUBLE | 影响半径；与岛中心距离 ≤ 半径即进入岛屿 |
| rules | JSONB | 岛主规则，3–5 条自然语言（需 AI 检查，冲突时全局规则优先） |
| resource_direction | TEXT | 资源方向描述（AI 归类到资源注册表） |
| buildings | JSONB | 岛上建筑列表 |
| defenses | JSONB | 岛上防御列表 |
| monster_config | JSONB | 怪物配置：种类、最高等级、数量、是否集中、集中点（见 1.5） |
| threat_budget / threat_used | NUMERIC | 岛屿总威胁度预算 / 已用（按世界日） |
| max_monster_level | INT | 最高怪物等级（≤ 当前版本强度上限） |
| visit_count | INT，默认 0 | 被访问次数（创建者面板可见） |
| resources_taken | INT，默认 0 | 被拿走资源量（创建者面板可见） |
| owner_character_id | UUID FK characters，可空 | 当前岛主（驻扎流转）；为空表示无主 |
| created_world_day / last_visit_world_day | INT | 创建世界日 / 最后访问世界日 |
| status | TEXT | `active`（岛屿永久存在，不沉没） |

### 1.7 monsters（怪物实例）§4.2

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID PK | 怪物实例 ID |
| kind_id | UUID FK monster_kinds，可空 | 预置种类；自定义怪物为空 |
| custom_name / custom_stats | TEXT / JSONB | 自定义怪物的名称与数值（需强度校验） |

| skills | JSONB | 该实例技能（从预置库选取） |
| created_world_day | INT | 生成世界日 |

### 1.8 items（物品）§4.2

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID PK | 物品 ID |
| name | TEXT | 物品名 |
| type | TEXT | 标签：`fuel`（燃料）/ `part`（零件）/ `weapon`（武器）/ `medicine`（药品）/ `tech`（科技）/ `food`（食物）/ `water`（水）/ `misc`（杂项）；效果由标签决定 |
| tags | JSONB | 扩展标签 |
| quantity | INT | 数量 |

| x / y | DOUBLE，可空 | 地面掉落 / 藏匿点坐标；死亡掉落永久保留 |
| created_at | TIMESTAMPTZ | 创建时间 |

### 1.23 关系与索引

- user 1—N character；character N—1 ship（乘船）/ N—1 team / N—1 island（所在岛屿）；island N—1 creator（user）；island 1—N island_points / monsters；monster N—1 monster_kind；character 1—N items / crystals / skills / experience_logs；channel 1—N chat_messages；island 1—1 channel（子频道）。
- 索引：`characters (x, y)`、`ships (x, y)`、`islands (x, y)`、`monsters (x, y)`（遭遇与距离查询）；`chat_messages (channel_id, created_at)`；`experience_logs (character_id, world_day)`；`items (owner_type, owner_id)`；`crystals (holder_type, holder_id)`。
- Redis（不落库）：在线状态（character_id → status）、频道成员、战斗回合定时器、移动节流、每玩家当日 AI 调用计数（与 `ai_quotas` 同步）。

## 2. 接口定义

### 2.1 WebSocket 事件（实时主通道）

客户端 → 服务端：

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `auth` | `{ token }` | 登录鉴权 |
| `move` | `{ angle, distance_nm }` | 任意方向移动；单次最长 2 世界小时（20 海里） |
| `drift` | `{}` | 随机漂流 1 世界小时（10 海里），随机方向 |
| `enter_island` | `{ island_id }` | 进入岛屿（加入岛屿子频道） |
| `leave_island` | `{}` | 离开岛屿（回到海频道） |
| `chat` | `{ channel_id, text }` | 发送聊天消息（过内容检查，见 §4.4 / §4.5） |
| `combat_action` | `{ combat_id, action, target_id?, item_id? }` | 回合行动：`attack` / `defend` / `use_item` / `flee` / `skill` |
| `island_create_start` | `{}` | 开始造岛：进入对话式模板 |
| `island_create_answer` | `{ question_id, answer }` | 回答模板问题（AI 按回答追问） |
| `island_create_confirm` | `{}` | 确认汇总，创建岛屿 |
| `island_create_cancel` | `{}` | 取消造岛 |
| `settle` | `{ island_id }` | 驻扎岛屿（建基地） |
| `trade_propose` | `{ target_id, offer_item_ids, want_item_ids }` | 发起交易；服务端校验双方同地（当面交接） |
| `dead_drop_place` | `{ item_ids, x, y }` | 藏匿交接：放置物品到坐标 |
| `dead_drop_take` | `{ drop_id }` | 取走藏匿点物品 |
| `follow` | `{ target_id, on }` | 跟踪 / 取消跟踪目标玩家 |
| `logout` | `{}` | 下线；战斗中拒绝，断线宽限期 30 秒 |

服务端 → 客户端：

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `position` | `{ x, y, world_day, world_hour, day_night }` | 位置与世界时间播报 |
| `narration` | `{ channel_id, text, kind }` | AI 叙述（航行 / 遭遇 / 探索 / 战斗结果） |

### 2.3 后端模块接口（TypeScript）

```ts
// 模型池：按优先级选择；同优先级按 key 随机；失败自动切换同种内下一个
interface ModelPool {
  select(tier: 'large' | 'small', key: string): Model;
  reportFailure(modelId: string): void;
}

// AI 网关：只负责调用；路由与配额由上层决定（复用英语平台 Router + Gateway 思路）
interface AIGateway {
  call(tier: 'large' | 'small', purpose: string, prompt: string, opts?: CallOpts): Promise<string>;
}

// 内容审核层：调用前与调用后双重检查（§4.4、§4.5）
interface ContentFilter {
  checkInput(text: string): { ok: boolean; categories: string[] };
  checkOutput(text: string): { ok: boolean; categories: string[] };
}

// 裁决器：纯数字裁决，不调用 LLM；AI 不得改写判定结果
interface Adjudicator {
  resolve(intent: Intent, ctx: GameContext): Resolution;
}

// 叙述器：模板优先，必要时 LLM 润色；高频场景复用缓存
interface Narrator {
  render(res: Resolution, ctx: GameContext): Promise<string>;
}

// 世界时钟：每 20 现实秒推进 1 世界分钟；昼夜、洋流、事件、怪物成长、疲劳 / 猝死判定
interface WorldClock {
  tick(): void;
}

// 岛屿服务：随机放置（间距、出生区禁建、威胁预算校验）、规则校验（含内容红线审查）
interface IslandService {
  place(draft: IslandDraft): Island;
  validateRules(rules: string[]): { ok: boolean; issues: string[] };
}

// 战斗引擎：服务端定时驱动回合；按速度排序；超时默认防守
interface CombatEngine {
  start(participants: Combatant[]): CombatSession;
  submitAction(sessionId: string, actorId: string, action: Action): void;
  resolveRound(sessionId: string): RoundResult;
}

// 成本配额：每玩家每日 AI 调用预算；超预算降级为模板叙述
interface CostQuota {
  check(userId: string): { allowed: boolean; degraded: boolean };
  record(userId: string, calls: number): void;
}
```

### 2.4 关键流程

1. **移动与遭遇**：`move` / `drift` → 服务端按距离与船速折算世界时间消耗，推进该玩家世界时钟，扣除燃料与物资 → 按密度判定遭遇（2 世界小时必遇兜底：连续航行 2 世界小时未遇岛屿时，洋流导向最近岛屿）→ 返回 `position` + `narration` + 可能的 `encounter`。
2. **战斗一回合**：`combat_round_start`（15 秒限时）→ 玩家提交 `combat_action`（超时按防守）→ 服务端按速度排序结算（怪物默认攻击最近玩家，4 级以上可指挥集火；怪物血量 ≤30% 时判定逃跑）→ `combat_round_result`（数字结算 + AI 一回合一条叙述）→ 下一回合。
3. **造岛（模板对话）**：`island_create_start` → 服务端逐条发送 `island_create_question`（怪物种类 → 最高等级 → 数量 → 资源类型与数量 → 建筑 → 防御 → 是否集中及集中点 → 补充规则；AI 按回答追问，可选可跳过）→ `island_create_summary` → `island_create_confirm` → 校验（强度上限、威胁预算、内容红线）→ 随机放置 → `island_created`（不返回坐标）。
4. **晶核吸收与升级**：怪物死亡掉落晶核 → 玩家吸收（能量计入 `crystal_energy`；越级吸收只吸收一部分，剩余留在晶体中）→ 满 10 颗同级晶体能量升级 → 固定等级领悟技能（AI 按最近 2 世界日 `experience_logs` 从预置技能池选择，写入 `skills`）。
5. **死亡与复活**：死亡 → 全部物品掉落原地（`items` owner_type = `ground`，永久保留）→ 复活于初始船只，海域内随机坐标 → 原船只保留原地，可取回；船长死亡后船只可交团队其他人驾驶。
6. **世界推进**：`WorldClock.tick()` 每 20 现实秒推进 1 世界分钟 → 昼夜切换（0–959 世界分钟为白天，960–1439 为夜晚）、洋流方向更新、触发 `world_events`、怪物按世界日成长、疲劳累积与猝死判定（连续 3 世界日疲劳起，30% + (天数 - 3) × 25%，封顶 100%）。
