## 1. 项目概述

- **目标**：做一个末世海上漂流纯文字聊天室游戏——玩家开船在连续坐标海上游荡，遭遇玩家创建的岛屿，限时回合战斗、收集资源升级船只，可驻扎建基地、可抢岛、可交易；怪物掉落晶核供人物升级，怪物随世界时钟变强、变聪明；世界演变由 AI 推进。
- **范围**：Web 端先行（先 Web，验证玩法后再考虑 App / 小程序）；不做 3D / 画面；MVP 之后才做 PvP 与夺岛、交易、驻扎基地、团队系统、晶核与技能成长、怪物智慧升级、GM 后台（见设计说明 §5）。
- **非目标**：本任务书不含美术、音乐、市场投放；商业化只做到方案探讨（M4），上线时不强制付费功能。
- **技术选型**：TypeScript + NestJS 模块化单体，PostgreSQL + Redis，WebSocket 实时通信，LLM 路由（复用 L0–L3 路由思路）；部署复用现有新加坡服务器。

## 5. 测试与验收

- 每个里程碑结束时按验收标准逐项验收，验收通过才进入下一里程碑；验收不通过则修补后复验，排期顺延。
- 测试分三层：单元测试（裁决、数值计算、晶核能量、猝死公式等纯逻辑）；接口测试（WebSocket 事件、REST 接口）；端到端测试（注册 → 建角 → 移动 → 遭遇 → 战斗 → 升级 → 造岛 → 驻扎 → 交易 → 夺岛全链路）。
- 内容安全专项测试：每里程碑回归红线拦截（色情、虐待、歧视、极端血腥、极端主义）与 AI 行为边界（闲聊不响应、医疗建议拒绝、自杀 / 毒品 / 枪支弹药 / 危险品制作方法拒绝）。

## 6. 上线标准（全部满足才上线）

1. 核心循环完整可玩：移动、遭遇、战斗、收集、升级、造岛、驻扎、交易、夺岛、团队均可用。
2. 内容红线过滤生效：拦截率达标，误拦截可接受；审核记录完整；违规梯度可执行。
3. AI 行为边界生效：闲聊不响应；医疗建议拒绝；自杀 / 毒品 / 枪支弹药 / 危险品制作方法拒绝。
4. 性能达标：压测通过（并发与 AI 调用峰值在预算内）。
5. 数据安全：备份与回滚演练通过；死亡掉落、晶核、岛屿数据无丢失。
6. 严重 Bug 清零；已知非严重问题有记录与排期。

## 7. 风险与应对

| 风险 | 应对 |
| --- | --- |
| AI 成本超支（调用量起来很贵） | 模板化叙述 + 缓存 + 每玩家每日预算 + 超预算降级；M5 内测核对实际成本 |
| 内容安全出事（红线内容漏网） | 调用前后双重检查；内测与公测专项复核；举报 → 审核 → 处置闭环 |
| 数值失衡（太难 / 太简单、刷资源） | 待定参数先行建议值，M5 按实测调；防自肥（坐标随机、创建者不可见） |
| 单人开发进度拖延 | 里程碑按周复核；验收不通过则顺延，不赶工上线 |
| 玩家流失（遭遇太空、内容太少） | 2 世界小时必遇岛兜底 + 洋流引导；M5 看留存数据再调密度 |
